# CRY WOLF! Storybook Slide UI v0.1
## Codex Implementation Task / 1夜分の絵本スライド化

**対象:** 『CRY WOLF! Romantic Variant』、独立Playable Experiment v0.5「二人だけの遠吠え」NIGHT 2「来ないって言ったのに」  
**優先度:** P0（ゲームの伝わりやすさと感情移入の検証）  
**実装方針:** **既存のゲームルールを変えず、情報提示・演出・画面構成だけを変更する**  
**ターゲット:** スマホ縦 360×800 / 720×1280、PCブラウザ。初見2〜3分、再挑戦1分前後を目標  
**技術:** **既存 v0.5 は HTML + CSS + Vanilla JavaScript の単一ファイル**。今回のためにReact/TypeScriptへ移植しない。Git repo上ですでに別実装に移行している場合は現物を優先し、差分実装の方針を報告する。

## 0. まず確認すること（ソースの現状）

開発の起点は、提供された `cry-wolf-v05-prototype/index.html` または `CRY_WOLF_v0.5_PLAY.html`。

v0.5で確認済みの事実：

- フェーズは `title → intro → night（2刻の行動）→ report → result`。
- 夜の3行動は `track`（足跡）／`listen`（耳を澄ます）／`signal`（二度のランタン合図）。いずれも1刻を消費する。
- 夜の開始時にルナは遠い森にいる。**最初の刻で送る合図は遠すぎて届かない**。1行動後は境界近くへ移動する。**2刻目に合図すると届き、境界外で待つ**。
- 合図が届かないまま2刻が終わるとルナは見張り道へ入る。
- 2刻終了後に必ず `cry`（警報）か `silent`（異常なし）を選ぶ。
- 合図が届いて異常なしならBEST、届いて警報ならFALSE、届かず警報ならDUTY、届かず異常なしならSECRET。
- **BESTの最初の行動は足跡調査でも音の調査でもよい。** v0.5では `track → signal` も `listen → signal` もBEST。既存仕様を崩さないこと。
- 結果の数値変化は BEST＝信用±0／きずな+1、FALSE＝信用−2／きずな±0、DUTY＝信用+1／きずな±0、SECRET＝信用−1／きずな+1。
- 現行キャラ画はHTML内のインラインSVG、テキストとボタンはHTML描画。オフラインで動く。テスト用 `window.CRYWOLF_TEST` あり。
- v0.5独立試作であり、7夜本編やv0.4のセーブとは**未接続**。今回も勝手に結合しない。

**資料上の矛盾を解消する決定事項:** 以前のラフ画面割りには「BESTは足跡メモ必須」「調査1回で途中報告できる」「GOOD WORKの信用+0」と読める記述があるが、**本タスクでは上記v0.5実装済みルールを正とする**。UI比較実験のため、判定ルールを混ぜて変えない。

## 1. この実験の仮説

> 情報を1画面に詰め込むより、「夕方の予告 → 夜の異変 → 自分で調べる → 合図を送る → 報告する → 二人の反応」の順で絵本のページをめくるほうが、プレイヤーはルールを理解し、キャラの気持ちを読み取り、選択の結果に納得できる。

**検証するのはUI/演出の効果**。シナリオの全面改稿、7夜の実装、リアルタイム動揺ミニゲーム、ステータスの追加、乱数の導入は**対象外**。

### UX原則

1. **1ページ1つの発見または感情**。選択が必要なページ以外に長い説明欄や複数の操作ボタンを同時表示しない。
2. 絵と文を分けて描画し、**日本語・選択肢を背景画像に焼き込まない**。
3. **夜の調査中はルナの姿を見せない**。夕方および結果のページでは登場してよい。姿で正解をネタバレしない。
4. プレイヤーが考える時間は無制限。**刻はゲーム行動を選んだときだけ進む**。文章送り、調査結果を読む、メモ確認、ヘルプでは減らない。
5. 知識は隠しても、操作ルールは隠さない。「森の遠くにはランタンが届かない」「2刻で報告」と最初に教える。
6. 失敗結果は自責の罰ではなく因果の説明。正しい仕事を選んでもルナはベルの誠実さを理解できる。

## 2. 画面の基本レイアウト

スマホ縦を基準に、以下の領域を用いる（割合は厳密な固定寸法ではなく優先関係）：

```
┌───────────────────────────┐
│ NIGHT 2 / 7       🏮 残り ●●  [?] │  ヘッダー8〜12%
├───────────────────────────┤
│                           │
│    余白を広く使う絵本イラスト │  主役の絵 50〜62%
│    ベル／ルナの立ち絵         │
│    月・森・足跡／ランタン     │
│                           │
├───────────────────────────┤
│ ルナ「今日は行かないってば」  │  テキスト14〜22%
│ （必要なページは2〜3行以内）  │
├───────────────────────────┤
│       ［つぎへ］             │  操作12〜25%
│  選択ページだけ大きなボタン   │
└───────────────────────────┘
```

- 選択ページはイラストを少し縮め、**選択肢を画面最下部より上に優先配置**。3ボタン＋補足が360×800に収まらないときはコンテンツ領域を縦スクロール可能にし、操作を画面外へ隠さない。
- 行動数表示は夜・報告ページで意味を持つ。夕方・タイトルでは必要最小限。
- 日本語本文は原則15〜18px、選択肢16px以上、タップ領域の高さ44px以上、色コントラストを保つ。
- `100dvh`/`100svh`、安全領域 `env(safe-area-inset-bottom)`、小画面と拡大表示へ配慮。絶対配置の文字が立ち絵に重ならないようにする。
- ページ送り操作は「次へ」明示ボタンを基本とし、**絵のタップで意図せず確定選択しない**。
- キーボード: Enter/Spaceで「次へ」（選択ボタンにフォーカス中はそのボタンのみ実行）、Escapeでヘルプを閉じる。フォーカス表示、`aria-live`を適切に用いる。
- アニメーションは短いフェード/ページ移動（150〜250ms程度）。`prefers-reduced-motion: reduce` で省略。連打で二重適用しない。

### S04の差分台詞・絵の指定（行動2種類の時刻差を扱う）

| 行動 | 1刻目（行動前 `ticks=2`） | 2刻目（行動前 `ticks=1`） |
|---|---|---|
| `track` | 小さなウサギの足跡。大きなオオカミの足跡はまだ境界の外 | 新しいオオカミの足跡が境界の手前まで続いている |
| `listen` | 長い遠吠えは森の奥から。だんだん近づく音 | 遠吠えはすぐそば。境界の外の木陰にいると分かる |
| `signal` | ランタンを二度遮ったが光は霧に消える。届かない | ランタンを二度遮る。短い返事。**ルナは境界の外で待ってくれた** |

- 合図は「二度遮る」で統一。「二連の遠吠え」と混同させない。
- 一度だけ、画面上で**現在の距離と灯りの届く範囲**を示す（曖昧な演出だけで不発を判定させない）。
- `S05`では1行動を終えてルナが近づいたことを絵とテキストで必ず示す。**プレイヤーがメモを取得できなかったとしても、距離の変化は伝える**。
- 途中の「もう報告を決める」ボタンは追加しない。現行仕様の**2刻終了後に必ず報告**に合わせる。
- 1行動を選んだ瞬間に`tick`を確定し、S04の「つぎへ」を押したときに**再び減らさない**。

## 4. 4結果の判定と数値（最重要・変更禁止）

**2刻終了時点の `signal` が `held` ならルナは境界外、そうでなければ見張り道に入った。** 最終選択の正しさはこの状態で判定する。

| 夜の2行動の例 | 終了時のルナ | 最終報告 | 結果ID | 信用 | きずな |
|---|---|---|---|---:|---:|
| `track → signal` / `listen → signal` / `signal → signal` | 境界外（後半の合図が届く） | 異常なし | `best` | ±0 | +1 |
| 同上 | 境界外 | 鐘 | `false` | **−2** | ±0 |
| `track → listen` / `signal → track` / `track → track` など、**後半合図なし** | 見張り道の内側 | 鐘 | `duty` | **+1** | ±0 |
| 同上 | 見張り道の内側 | 異常なし | `secret` | **−1** | +1 |

※ `signal → signal` は1刻目不発、2刻目成功としてBESTに到達可能。これも既存ルールに含まれる。  
※ 1刻目に `signal` を送っただけでは成功扱いにならない。  
※ 「調べたら正解」ではなく、**2刻目に有効な合図を送ったか**が実際の状態を変える。  
※ 正しい警報 `duty` で信用+1。以前のラフ資料の「+0」へ戻さない。

**結果ページの必須順序:** 「何が起きた」→「ルナ／ベルの感情表現」→「なぜその結果か・変化値」。「正解！」「失敗！」の大きな採点演出より、物語の因果を先に見せる。

## 5. 表情・絵・音の演出指定

### アートディレクション

- フラットポップな絵本風。**夜紺 `#19283F`、月白 `#F4EAD9`、ベルの黒白、ルナの銀毛、赤リボン `#D54760`**を基本とし、金の鐘・ランタンだけ少し明るく扱う。
- 大きな満月、森と村のシルエット、余白、面積の広い色面。背景の窓や花を細かく増やしすぎない。
- ベル：片折れ耳、白い顔の筋、ランタン、警報ベル。ルナ：三角の狼耳、銀髪、大きな尻尾、赤リボン。
- **顔・耳・尻尾の表情を最優先**。精細な衣装、粒子エフェクト、装飾枠は簡略化する。
- ルナが本当に来たかどうかは、S03〜S06で立ち絵を出さないことで守る（夜景に影を描く場合も、狼だと確定できる姿は禁止）。

### 必要な画面アセット（優先順位）

| 優先 | アセット | 差分 | 実装の扱い |
|---|---|---|---|
| P0 | タイトル／夜の背景 | 月夜・夕方・境界・朝 | 最初は現行SVGの調整で可。別画像必須ではない |
| P0 | ベル立ち絵 | 通常・考え中・照れ・決意 | 既存SVGを使えるなら改修して流用 |
| P0 | ルナ立ち絵 | 強がり・からかい・照れ・待っている | 既存SVGを使えるなら改修して流用 |
| P0 | 調査の寄り絵 | 足跡／耳を澄ます／ランタン | コストを抑えたシルエット・図形表現で可 |
| P1 | 小さなパーツ | 鐘、ランタン、境界線、リボン、メモ帳 | SVGやCSSで制作 |
| P2 | 表情アニメ | 耳ぴく、尻尾ぱた、リボン揺れ | `transform`等による簡易演出。未実装でも合格可 |

**既存の生成画像の注意:** ポスターや設定画に日本語タイトル・説明文・UIが焼き込まれているものは、**そのまま操作画面の背景に使用しない**。現行SVGの絵柄を磨くか、後から背景と人物の別レイヤー画像を差し込める構造にする。

### 音

- `S02`: 遠吠え（音声アセットがなければ短いテキスト＋控えめな効果音で可）。
- `signal` 成功: 光が二度点滅、遠くから短い返事。
- `cry`: 鐘。音量は控えめで明示的なON/OFFを保持。
- BGM追加はP2。ブラウザのユーザー操作開始前に音を再生しない。**音を消してもすべての情報が文字と絵で分かる**。

大規模リライトを避ける。現行 `index.html` にインラインCSS/JSがあるため、まず既存動作を保全し、必要最小限の分離を行う。

```js
  signal: 'none',  // none | miss | held

  // action取得時のticksで、合図の届く距離を決める。
  // 効果適用→ticks--→観察用slideIdへ。
}

function resolveReport(state, report) {
  // 既存: signal === 'held' と cry/silent の組み合わせで4結果を確定。
}

function advanceSlide(state) {

```

- `slideData` にテキスト・人物表情・背景・ボタン定義を置く。画面用HTML内へ長い台詞を散らさない。
- `renderSlide(game)` と `applyNightAction(game, action)` と `resolveReport` を論理的に分ける。新しい依存ライブラリは不要。
- 選択肢テキストはHTML要素に表示。音・アニメーションは `prefers-reduced-motion` とミュートに対応。

- 開発中に二重クリックやEnter連打で**状態が二重進行しない**ようにする。画面遷移中の入力は無視するか同じイベント処理をガードする。
- `S08`の「もう一度」は状態を完全リセットし、INTROから繰り返せる。**7夜本編の「次の夜」はまだ設けない**。

## 7. 実装順（Codexへのタスク）

- `v0.5`の単独HTML版は複製またはタグで退避し、比較可能にする。

## 8. 自動テスト / QA受け入れ条件

### ロジック回帰テスト（3^2 × 2 = **18通り**）

1刻目・2刻目の全組み合わせ（`track/listen/signal` × `track/listen/signal`）に、警報/異常なしの報告を掛け合わせて**18通りをすべて検証**。期待結果は「2刻目の操作が`signal`なら `held`、それ以外は `held`でない」で決定する（1刻目の合図は不発）。

| ID | 手順 | 想定 | 備考 |
|---|---|---|---|
| T01 | track → signal → 異常なし | `best`／信用±0／きずな+1 | 王道の発見 |
| T02 | listen → signal → 異常なし | `best`／信用±0／きずな+1 | 足跡必須にしない |
| T03 | signal → signal → 異常なし | `best`／信用±0／きずな+1 | 1刻目不発→2刻目成功 |
| T04 | track → signal → 鐘 | `false`／信用−2 | 誤報 |
| T05 | track → listen → 鐘 | `duty`／信用+1 | 正しい警報 |
| T06 | track → listen → 異常なし | `secret`／信用−1／きずな+1 | 見逃し発覚 |
| T07 | signal → track → 鐘 | `duty` | 先走った合図の失敗 |
| T08 | signal → track → 異常なし | `secret` | 先走った合図の失敗 |
| T09 | 任意の1行動後、S04閲覧→つぎへ | `ticks=1`のまま | ページ送りで二重減算なし |
| T10 | 2刻目後のS04閲覧→報告へ | `ticks=0`, `phase=report` | 二重実行なし |

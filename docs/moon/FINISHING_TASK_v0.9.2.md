# CRY WOLF! / 月あかりの約束
## Title, Loading & Story Clarity Pass v0.9.2 — Codex Implementation Task

作成: 2026-10-12 / 対象repo: https://github.com/madowaku/cry-wolf

### 0. 目的と正本

**目的**: 現行の七夜絵本版を「起動した瞬間から一冊の絵本らしい」「初見でも何を楽しむか分かる」「画面の要点と選択の結果が読める」ものに磨く。物語やゲーム性を拡張するタスクではなく、体験の伝達と品質改善。

- 最新の `main` / 作業ブランチを取得・確認し、作業開始時のHEADと差分を記録する。こちらで確認した時点の基準は **`public/moon/` の v0.9.1**。その後更新されていれば最新を優先し、既存実装を上書きしない。
- 現在の実装は `public/moon/index.html`, `app.js`, `presentation.js`, `audio.js`, `model.js`, `story.js`, `story-late.js`, `style.css`, `assets/`、関連資料 `docs/moon/SEVEN_NIGHTS_v0.9.md`, `docs/moon/IMPORT_STORYBOOK_v0.9.1.md`。トップの旧React版と1夜版 `public/storybook/` は**比較用の旧系統**。
- **v0.9.1の7夜・4END・道の成立/不成立・3ページのエピローグ・保存/移行・BGM3曲は保持**する。画像素材（ベル、勝気なルナ、村長、ピップ）はそのまま使う。大規模な画像再生成、リライト、ゲームルール改訂、エンジン移行はしない。
- 文書だけではなく、**コードを実装し、画面と音の動作を検証してから**報告する。`AGENTS.md` を現行運用に更新する。

### 1. P0: 正式タイトル画面 = 既存ホームを改修

**背景**: `app.js` は既に `home` 分岐で「嘘つきの夜に、ほんとうの気持ち。」と「絵本をひらく / しおりから読む」を表示している。**新しいタイトルページを独立に積み増さず、既存ホームを正式な「表紙」に仕立て直す**。

#### ビジュアル
- 大きな半月（第一夜時点）、村と森の境界、**左右に少し離れて立つベルとルナ**を主役にする。ベルは真面目に鐘を持ち、ルナは最初からデレない「負けず嫌いなオオカミ」の表情。物語が進む前の距離感が伝わる構図。
- タイトル `CRY WOLF!`、副題「月あかりの約束」をUIの文字として配置。生成画像に文字やボタンを焼き込まない。
- 初期画面に**「村を守る犬、森を守る狼。七夜で、ふたりの答えを探す。」**程度の一文。長い解説・合図の攻略・結末のネタバレはしない。
- **音楽は既存の「the fairy tale / のる」を継続**。新規BGMを探さない・入れ替えない。ユーザーの最初の明示的な操作時に、既存の音設定に従い再生を許可する。ブラウザの自動再生制限を無理に回避しない。

#### 操作
- 新規ユーザー: 大きな `絵本をひらく` ボタンが第一優先。
- セーブがある場合: `しおりから読む` を主ボタンとして先に表示し、`最初から読む` は誤タップ時に確認を挟む。**保存データ・読了END履歴を消去しない**。
- `設定` / `遊び方` は到達しやすいが、タイトルの主役にしない。可能なら `読んだ結末 n/4` を小さく表示。ただしアンロック済みのEND名はタイトルでネタバレしない。
- ESC/キーボード、44px以上のタップ対象、360×800と390×844、PC横長、画像未読込時のレイアウトを確認。ボタンの視認性と主従を明確に。
- `home` 表示はゲーム進行・`revision`・`events`・刻を進めない。タイトルへの戻りも同様。

### 2. P0: ローディング画面 = 絵本を開く前の短い時間

**目的**: 読み込み時の真っ白/暗い無反応画面を減らす。最短で表紙へ。**固定2秒待ちなどの演出待ちは導入しない**。

#### 表示
- 夜紺 `#19283F` 背景、半月・小さな鐘のシルエット、`CRY WOLF!` と一行 `月あかりの絵本をひらいています…`。
- 月の切り替え/鐘の控えめな動き（CSS）。`prefers-reduced-motion` / 設定「動きOFF」を尊重する。
- 進捗の数値％は**計測できる場合だけ**。計測できないなら「読み込み中…」表示でよい。架空の進捗・ロード失敗の無限ループは不可。

#### 開始/完了/失敗
- `index.html` 内の極小CSS/DOMでJavaScript本体読み込み前から描画可能にする（構造がより簡潔なら別方式も可）。タイトル用の背景と主役画像、ゲームの初期化が可能になれば消える。
- 37点の全画像・全音楽デコードを待たない。遅い端末でも、必要最小限を用意して表紙へ移る。ゲーム中の後半画像は必要時に読む。
- 音源はユーザーの操作まで再生しない。**ロード解除時にBGMを重複起動・先頭リセットしない**。
- 通信不良/アセット失敗は明確なフォールバックと `再試行` / `画像なしで続ける` 等の現実的な復帰経路を用意。`file://` と開発サーバー/配布ZIPの両方で利用可能。
- ブラウザの戻る/再読込/既存セーブ再開でもローダーが残らない。読み込み中の要素には適切な `role=status` または `aria-live` を付け、フォーカスを行方不明にしない。

### 3. P0: ① 序盤に「この物語で何を目指すか」を一言だけ

**守るもの**: 『オオカミ少年』→ベルの仕事→ピップの手紙→ルナの登場、という現在の4ページ導入。説明文を大量に追加しない。

- `story.js` の **ピップの「七夜後、道が閉じる」** の後、ベルの心の声に一文を自然に入れる。候補: `「村を守るのが僕の仕事。でも、手紙が届かなくなるのも困る。……道を残す方法はないのかな」` 。初夜のルナ登場前にルナの秘密や最終解決は語らない。
- **第一夜の決断直前**は「オオカミが見張り道の内側に入れば正しい警報が必要／今夜は実際に入っている／黙ると朝の足跡で分かる」という既存の説明を保持。ここを曖昧にしない。
- 初夜結果にはベルの選択が「村との関係 / ルナとの関係」に何をもたらしたかを明確にし、プレイヤーの目的と行動をつなぐ。ゲームの最適解や将来の恋愛結末を示唆しすぎない。
- 初見が序章後に「なぜ夜番をするのか」「なぜ道を閉じると困るのか」「自分が何を考えて選ぶゲームか」を説明できる構成にする。

### 4. P1: ② 鐘・月・境界石の情報設計

**全面的な美術刷新はしない**。すでにある絵本風背景・立ち絵とBGMは保持。ゲームのルールを伝える重要小物を視覚的に整理する。

- **鐘**: 選択 `鳴らす` の場面で主役。目線が鐘へ向く構図、光沢/輪郭/距離感を整理。鳴らす場面だけ既存の音/動きで反応。警報していないのに鐘が鳴ったように見せない。
- **月**: 第一夜半月→第七夜満月。既存 `CWModel.moon(stage)` と `moon()` を**単一の表示ソース**として維持。読み込み中やタイトルは半月、物語進行に応じて満ちる。セーブ再開でも正確な位相を表示。タイトルに戻った時は表紙の半月、読書途中の位相と混同しない。
- **境界石**: `見張り道（村側）/森側` と「境界を越えたか」がスマホでも一瞬で区別できること。第二夜・第五夜の判定に関わる重要事実なので、色だけでなく位置/文字でも区別。**ルナの居場所を知らない調査中に真相を表示してネタバレしない**。
- 各ページで主役の視覚情報は**1つ**。装飾の追加で文字/表情/選択肢を小さくしない。必要なら既存のSVG/CSSを調整し、画像素材追加は最小限に。

### 5. P1: ③ 村の信用・きずな・合図の理解を初見にも分かる表示へ

現在のモデルに存在する公開値と範囲（勝手に変えない）:

| キー | 画面名称 | 初見向け説明 | 範囲 |
| --- | --- | --- | --- |
| `trust` | **村の信用** | `村のみんなが、ベルの報告をどれだけ信じているか` | 0〜5 |
| `bond` | **ルナとのきずな** | `ルナがベルをどれだけ信頼し、本音を話せるか` | 0〜5 |
| `insight` | **合図の理解** | `ランタンや遠吠えを、二人で使いこなせた経験` | 0〜3 |

重要: 内部 `honesty` は最終の第三選択肢の判定に関係するが、**`insight` と混同しない**。現行 `canCall` は `bond>=4 && trust>=2 && honesty>=1`。勝手に「合図の理解を一定値にするとTRUE」と説明しない。

- 最初にステータスが現れたとき、1度だけ短い説明を置くか、それぞれの項目に常時短い意味を添える。ゲーム中は手帳/ヘルプでも再確認できる。
- 結果画面（現在 `app.js` の `result` + `readingStep===1`）では `信用 3 → 4（+1）` など**変化前→変化後、実際の増減、理由**を読みやすく提示する。変化0も必要に応じて `変化なし`。上限・下限で加減算できなかった場合は**実際の差分で**表示。内部の予定deltaをそのまま描かない。
- 結果を読む順番は現行どおり**二人の表情と反応 → 理由と数値**。表情を見る前に大きなスコア表示を押し付けない。
- 360×800では数字・説明が小さくなり過ぎない。本文の可読性を落とさず、ゲージだけで意味を伝えようとしない。11px級の小さな差分文字（例: `.changes`）は改善対象。
- 例: 第一夜 `ring1`: 信用3→4、きずな0→0。`hide1`: 信用3→2、きずな0→1。第二夜 `false`: 信用を2減らす等、現行モデルと一致。数値の意味は「得点」ではなく物語内の反応で理解できるように。

### 7. 実装順序

1. **現状保護**: git status、ブランチと最新差分を確認。現行の `moon/` の画面、保存キー、BGM、7夜ENDテストを把握。必要なら作業ブランチ作成。
2. **AGENTS.md更新**: 本番対象と旧版を分ける。READMEも必要箇所だけ現行版へ整合。
3. **タイトルとロード**: まず絵本の表紙を作り、ロードの成功・失敗・瞬時完了時の動作を確認。
4. **①②③**: 目的の台詞、重要小物、ステータス説明と結果UIを改善。
5. **テストと比較**: 以前の画面と改修後をスクリーンショット比較。4ENDと道の成否、セーブ、BGMを回帰。
6. **成果報告**: 変更ファイル、before/after画像、7夜全ENDテストの実際の結果、実機未検証事項、次の人間テストの質問を記載。

### 10. 初見プレイテストの質問（人間が後で確認）
